# 大文件操作、远端搜索与有界状态管理规格

状态：依据已确认访谈形成的实施规格，尚未实施。2026-09-13。
本规格覆盖 ADR 0006–0011；首版行为保留在 contracts.md 中作为迁移基线。新增技术默认值是本规格的工程选择，不声称由用户逐项指定。
关联：GitHub #3；远端 Windows 完整适配另见 #4。

## 1. 问题与目标

当前 remote/files.py 在 snapshot 入口拒绝超过 16 MiB 的文件，并把全文读入内存；分块下载会对每一块重复执行全文快照。remote/discovery.py 跳过大文件。局部操作因此无法处理 200 MB 网表。

目标是在文件所在服务器完成扫描与修改，仅回传有界片段；完整传输才承担全文网络流量。取消文件体积门槛，用流式处理、执行预算与空间额度约束资源。临时文件和结果必须有可执行的回收规则。

本轮目标环境为 CentOS 7、Python 3.6 标准库、无 root、离线部署。本机可使用现有 Node.js 运行时；这不代表远端 Windows 存在 Node.js。

## 2. 用户故事

1. 作为 Agent，我希望只读取大网表中的目标片段，以便减少网络和上下文开销。
2. 作为 Agent，我希望在服务器搜索内容和文件名，以便快速定位需要读取的位置。
3. 作为用户，我希望搜索能包含被 Git 忽略的生成文件，并可选择启用忽略规则，以便控制搜索范围。
4. 作为 Agent，我希望重复原文匹配时得到明确拒绝，以便扩大上下文后准确修改。
5. 作为用户，我希望外部修改导致旧读取凭据失效，以便减少误覆盖。
6. 作为 Agent，我希望整体覆盖只需明确覆盖意图并核对目标版本，以便无需读完旧文件。
7. 作为用户，我希望上传和下载断线后续传，以便不重复传输已完成的数据。
8. 作为 Agent，我希望传输在后台运行并回传完成结果，以便同时处理其他工作。
9. 作为用户，我希望源文件变化或校验失败被明确报告，以便不会获得混合版本文件。
10. 作为用户，我希望取消传输后及时删除未提交数据，以便释放空间。
11. 作为用户，我希望提交时断线先核对原操作，以便避免重复覆盖。
12. 作为用户，我希望结果和临时文件到期自动清理，以便不会无限积累。
13. 作为 Agent，我希望过期结果明确不可恢复且旧请求不能重跑，以便避免重复执行。
14. 作为用户，我希望空间不足时拒绝新增占用并可按需查看用量，以便控制磁盘开销。
15. 作为用户，我希望修改已有绑定的指定配置并自动生效，以便无需重新配置认证。
16. 作为用户，我希望旧任务在升级后仍可跟进，以便升级不会丢失在途工作。
17. 作为 Agent，我希望通过远端 Shell 管理目录、移动和删除，以便减少专用工具数量。
18. 作为用户，我希望凭据过期后只重读需要修改的片段，以便不因清理机制增加全文读取成本。

## 3. 模块边界与改造次序

- FileService 和 workspace-server 保留 MCP 入口、会话归属与本机路径检查；不承载整文件缓冲。
- remote/files.py 的版本观察、片段读取、精确替换和提交分开。先在旧契约下抽取内部边界，再迁移，避免把重构与语义变更混在一次提交。
- remote/discovery.py 统一文件筛选、后端选择、分页及返回预算；后端适配器只负责扫描。
- 新传输服务管理事务、分块、恢复和后台 CLI；复用 SSH 连接设施，不复用逐块全文快照。
- 两端状态维护负责记录期限、资源登记、空间预留和清理；task-service、传输服务与文件提交共同使用。
- workspace-setup 与配置加载入口负责补丁式更新和策略重载。
- 测试优先沿现有 MCP stdio、job CLI、正式 Python helper 入口验证；仅时钟与故障注入需要窄测试入口。

采用先增加新协议、迁移调用方、最后移除旧路径的顺序。运行期混用新旧互斥协议不允许。

## 4. 文件读取与版本

### 4.1 版本观察

新增 remote_read 的 metadataOnly 模式：返回服务观察的目标版本或明确的不存在状态，不返回内容、不授予读取覆盖。用于 remote_write 和上传的覆盖前置检查。

Linux 版本包含设备号、inode、文件大小、mtime_ns 和 ctime_ns；使用描述符 fstat，并核对解析后的路径仍指向同一对象。所有版本均由服务生成，绑定工作区与规范路径。读取前后核对版本；编辑在锁内提交前再次核对。

取消每次读写的全文 SHA-256。元数据检查无法证明任意外部写入都可检测；本服务锁也不约束外部程序。不得宣称消除了所有竞态。符号链接、多硬链接写入继续遵循首版拒绝规则。

### 4.2 有界读取

取消 16 MiB 文件上限。默认流式缓冲 256 KiB；文本输出继续控制在序列化后 56 KiB 内，二进制调用亦受明确响应预算约束。maxBytes 是返回预算，不是文件大小上限。

按行请求需要从可知行边界扫描到目标；不能把行号直接当字节偏移 seek。返回带版本和下一字节偏移的游标，后续页直接续读。随机跳到远处行号可以有顺序磁盘扫描，但不传回前文、不缓存全文。不增加永久行索引。

超长行分块返回，包含行号、字节起止和行是否完整；UTF-8 字符不被切断。保留 BOM、CRLF 信息。无效文本明确报告编码问题，允许按二进制读取。

仅实际交付的字节范围计入 readToken。连续 3 天无成功相关读取或编辑过期；失败和查询不续期。过期不能复活旧范围。成功编辑映射已读范围并换发凭据，失败续签明确报告已提交，不能盲目重做。

### 4.3 精确替换与提交

oldText 在整个文件中恰好出现一次，完整匹配必须在有效已读范围内。零匹配返回需重读，多匹配返回歧义并要求扩大 oldText；不选择第一处、不模糊匹配、不隐式 replace-all。

分块匹配携带跨块尾部，保持首版匹配计数语义；多项替换保持既有顺序和原子性，任一失败不部分提交。使用同目录临时文件流式拼接，保留权限、BOM、换行。写入并 fsync，核对版本后原子替换，再同步目录及记录提交结果。

整体写入默认 create-only；覆盖需 overwrite=true 和 metadataOnly 获得的 expectedVersion。版本不符拒绝，创建时目标存在拒绝。无需旧全文已读，局部编辑保护不变。inline text/base64 仍受请求预算限制，大内容走上传。

临时文件必须先登记归属并预留空间。变长编辑可能需要重写整个文件，这会产生磁盘 I/O，但不产生全文网络传输。

## 5. 搜索与查找

### 5.1 范围与后端

Linux 内容搜索按远端可用性选择 rg → GNU grep → Python 分块字面量搜索。不自动安装，不把后端崩溃当作无匹配；已输出部分结果后不能无提示切换并制造重复。

保持字面量、UTF-8、大小写敏感的既有搜索语义；不新增正则。默认 respectGitignore=false、includeHidden=true；始终排除 .git 内部。只在显式启用时读取层级 .gitignore；不隐式引入全局 ignore 或其他 .ignore 文件。

公共筛选器负责边界、隐藏路径和 .gitignore，三个后端使用同一候选集合。需覆盖否定规则、目录规则、转义、嵌套和被忽略父目录不能直接重新包含子文件的语义。路径通过参数或 NUL 分隔传递，不拼接可执行 Shell 文本。

find 独立使用 rg 文件枚举能力或 Python 遍历；grep 不用于文件名枚举。glob 继续保持既有契约，通过公共筛选器校正后端默认行为。

### 5.2 分页与成本

每页序列化结果上限 64 KiB，默认扫描预算 512 MiB、最长 10 秒，可由受控配置调整；预算耗尽返回 partial、原因和可继续游标，不能返回“没有匹配”冒充扫描完成。取消单文件大小排除，200 MB 网表必须可搜索。

游标绑定查询、工作区、路径、当前文件版本、字节位置与行位置。已扫描文件不在后续页重新全文扫描；续扫当前文件时版本改变返回明确游标冲突。跨文件目录是尽力枚举，不承诺目录快照，期间新增文件需要新查询。

后端从当前文件偏移续扫时可通过受控输入流喂给扫描进程，重建行偏移；所有管道均有背压和输出上限。超长行按有界片段报告命中，跨块匹配不遗漏。二进制和编码错误计入有界跳过摘要，不能无声消失。

搜索结果不签发编辑读取凭据；Agent 仍须 remote_read 目标片段。能力结果报告实际可用后端，单次搜索返回实际使用后端。

## 6. 传输协议与后台体验

### 6.1 身份与状态

上传与下载采用相同事务结构，方向相反。两侧工作区 transfers/ 保存小型记录，接收临时数据位于目标同目录。记录包含 schemaVersion、工作区/会话、方向、源和目标版本、分块大小、已确认偏移、分块摘要、状态、实际进展时间、到期时间和资源登记标识。

状态为 prepared → transferring → verifying → committing → completed；另有 interrupted、cancelled、failed、unknown。传输状态与“结果已确认”分开。查询不启动新传输、不续期。unknown 表示尚未核实，不能伪装失败或完成。

请求由服务先持久化分配，之后才能启动；跟进、重试、提交只接受已登记标识，找不到记录一律拒绝，不走创建分支。创建是单独的显式动作。分配成功但响应丢失且从未启动的记录可到期回收，不会执行副作用。

对任务采用相同的“登记后执行”原则；删除记录后，旧标识无记录只能返回 REQUEST_EXPIRED_OR_UNKNOWN。禁止旧客户端以同一旧标识重新创建。无需永久逐条墓碑；协议版本及调用方迁移见第 9 节。

### 6.2 分块与提交

默认分块 1 MiB，每个工作区最多 2 个活动传输，每个传输单个在途块。使用独立 SSH 二进制流及有界控制帧，不将整文件 Base64 放入 JSON，也不让模型参与逐块调用。

接收块持久化并校验后再推进确认偏移；摘要清单按块追加并流式读取，不能随文件增大把整份清单载入内存。续传在两端检查源版本和已有分块，损坏块及其后数据从最近可信边界重传；源版本变化拒绝原传输。

最终两端各自流式 SHA-256，核对相同全文摘要后提交。校验不再跨网传输全文。上传、下载都检查源稳定性和目标版本。覆盖已有目标必须显式绑定观察版本；未覆盖默认目标不存在。

提交前持久化意图（目标预期版本、临时对象身份、最终摘要），提交后持久化回执。断线重连先核对回执与目标身份；证据不足保持 unknown，不盲目再次覆盖，也不把偶然内容相同当作原提交的证明。外部程序仍可能制造不可判断窗口。

### 6.3 公共入口

保留 remote_upload / remote_download，增加 start、status、resume、cancel、ack 操作，默认 start；后续操作只需 transferId 与 sessionId。start 返回持久标识和有界状态，不等待全文完成。所有方向均保持本机允许路径及远端边界检查。

扩展现有 job CLI，增加 transfer start/wait/status/resume/cancel/ack 子命令。由 ZCode 原生后台 Shell 执行传输等待器，等待器完成后输出有界结果；恢复钩子列出同会话待跟进传输并重新挂接原标识。不能依赖 MCP 服务内一个会随退出消失的 Promise 宣称持久后台完成。

断线时等待器有界退避；本机退出导致传输中断，重启后续传。无需把本机离线期间不能传输描述为失败。进度仅按需查询，后台不持续向模型投递每块消息。

## 7. 生命周期与空间

### 7.1 保留规则

| 数据 | 计时起点 | 默认期限/回收条件 |
|---|---|---|
| 已完成且确认的完整任务日志 | 结果 ack | 3 天 |
| 已完成且确认的小型任务/传输结果 | ack | 30 天 |
| 已结束未确认结果（任务与传输） | 结束 | 30 天 |
| 结果未知的结果、诊断、恢复记录 | 首次 unknown | 30 天，到期停止自动恢复并清掉 |
| 意外中断、无占用的传输临时数据 | 最后实际进展；未开始则创建 | 3 天 |
| 主动取消的未提交临时数据 | 确认停止 | 立即 |
| readToken | 成功的同会话同文件读/编辑 | 3 天 |
| 普通临时文件 | 成功或确定失败且不再需要 | 立即；崩溃残留在下轮核实后清理 |
| helper | 使用关系 | 当前版本及活动依赖保留，其他下轮清理 |
| 锁 | 固定槽 | 复用，不按历史请求新增 |

未知结果记录不能因人工尚未核对而无限保存。到期不推断操作成功、失败或已停止。正式文件不删除；仍被使用或占用未知的临时数据继续核实。资源管理只保留路径、对象身份、归属、占用证据、字节量等最小信息，不保留过期结果全文，且计入额度。

保留期变更不追溯已有记录的 expiresAt；查询与核实失败不续期。有效读写续签凭据视为新签发，采用当前策略；结果状态转换（如 ack）新建该阶段到期时间，已过期阶段不能通过晚到 ack 复活。

### 7.2 清理、锁和配额

启动、重连和操作时懒清理，并在 MCP 在线时默认每小时维护。每工作区跨进程互斥，默认每轮最多 100 项或 2 秒；后续轮次从持久游标继续。没有远端守护进程或 cron，离线到期在重连后补做。

资源登记必须在临时文件可被遗留前完成；清理核对真实路径、对象身份和占用，不能仅凭 .ssh-mcp 文件名前缀删除。进程占用证据结合 PID、启动身份及锁，不能仅凭 PID 重用或时间过旧认定无占用。

默认 256 个文件/任务锁槽，按稳定身份哈希映射；多个目标按槽去重、排序获取。锁使用期间不删除重建。状态账本锁独立，规定资源操作与账本操作顺序，禁止反向获取死锁。

本机与远端每工作区各 10 GiB，可配置。计入状态、日志、helper、预留及管理的临时数据，包含目标同目录文件；提交后正式目标移出计量。预留与已写占用不能双重计数。

已知大小传输及编辑启动前预留所需空间；任务日志等未知增量按有界块申请额度，不能无限增长。日志额度耗尽时停止保存新增日志并记录明确截断原因，继续排空输出避免阻塞子进程；输出丢失不能伪装完整可 ack。控制记录保留固定预算，避免满额后无法记录错误和清理进展。

额度不足先回收已过期且可删数据，仍不足拒绝新占用，不提前删除受保护数据。物理磁盘不足独立处理。活动预留不能仅凭超时回收，需核实占用。

remote_workspace 增加 includeStorage=false；开启时仅返回两端 usedBytes、reservedBytes、limitBytes、分类用量、最近清理时间及计数，最多 4 KiB。远端不可达时明确 unknown，不写零。维护不调用模型，schema 与样例的实际 token 数在交付时测量并记录模型/分词器版本。

## 8. 二次配置

remote_setup 增加 inspect/update 操作，现有首次配置保持兼容。inspect 返回脱敏配置与 revision；update 必须携带该 revision，只改显式字段，校验后原子保存。认证信息原样保留且不回显；并发冲突拒绝而不是覆盖。

策略字段集中在 policy：两端额度、各类保留期、搜索过滤及预算、维护间隔。未提供字段用默认值。普通策略每次操作/维护重新加载，已有操作固定使用启动时快照；降低额度不删除活动文件，阻止后续超额申请。

服务器、remoteRoot、状态目录等身份相关变化本轮不原地修改，通过新绑定完成；旧绑定保留以跟进和清理旧状态。拒绝更新时不留下半写 profile。

## 9. 兼容、工具收缩与交付

新增协议带版本握手。升级先进入排空状态：旧任务仍可查询和完成，新旧协议不能同时接收写入。确认旧写入/传输进程退出后切换固定锁与新启动协议，再开放新操作；不能静默强杀旧任务。

旧任务记录迁移为可观察记录；不允许旧“缺记录即启动”入口重新启动。已知终态使用原时间生成到期值；无法证明结束的记录进入 unknown 阶段，记录迁移观察时间。迁移幂等、崩溃可重试，未迁移完成不启用破坏性清理。

升级不能容许仍有不支持握手的旧写入客户端绕过切换门槛：部署步骤先停止这些客户端，检测未排空就拒绝切换。回退需对应离线包；新格式不兼容的旧版本拒绝写入。

移除 remote_move/delete/mkdir/rmdir 的注册及专用调用路径，更新 README、usage、contracts、恢复指引和离线包。Shell 移动删除不再拥有 readToken 保护；这不代表任何未来删除请求自动获授权。

## 10. 验收与测试门槛

每张功能票先添加能失败的行为测试，再实现；优先现有 workspace-mcp、remote-files、task-service、job-cli、setup 与真实 SSH 集成入口。时钟注入用于期限，无需真实等待 30 天。

- 200 MiB 非稀疏网表，首/中/末片段读取、跨块 UTF-8/CRLF、超长行、重复替换、外部改写；读到末尾不会将前文传回。
- 比较 20 MiB 与 200 MiB 同类文件的增量峰值内存；每活动操作增量目标不超过 64 MiB，10 倍文件不能导致近似 10 倍内存。测量本机 Node、远端 helper/扫描子进程合计，扣除空闲基线并记录方法。
- 搜索分页命中集合与顺序正确，覆盖三个实际后端、隐藏/忽略规则、字节预算与超时续扫；不跳过大文件。
- 上传/下载在块边界、半块、校验、提交前后断线或杀本机进程；恢复后摘要一致、正式目标无半成品、未知提交不盲重做。续传仅发送未确认部分及最多一个不完整块，不因最终校验重传全文。
- 在两次查询间删除结果记录，旧任务/传输标识不得启动副作用；跨会话/工作区伪造标识拒绝。
- 加速时钟覆盖所有期限；确认未知结果也被清理。占用中的临时文件、正式文件及无归属文件不被删除。
- 配额并发预留、满额日志、物理 ENOSPC、崩溃遗留、PID 重用、helper 活动依赖、固定锁碰撞与迁移故障。
- 二次配置保留认证、并发拒绝、无需重启、旧 expiresAt 不变、新记录采用新值。
- 默认 remote_workspace 不返回统计；按需返回有界汇总，记录工具 schema 与样例 token 成本。
- npm build/test、正式 Python 套件、CentOS 7 VM SSH 测试和 ZCode 后台完成/重启续传验收。最终内网离线现场验收单独列为未完成，不能由 VM 自动测试替代。
