# 短读取凭据

2026-10-12 用户确认并授权实施。目标是降低 Agent 回填 `readToken` 的复制负担，同时保留既有读取与编辑校验。真实 ZCode + GLM 5.3 Flash、Codex 与 CentOS 7 的使用效果仍待人工验收，不能把编号缩短表述为已经解决模型幻觉。

## 格式与取舍

- 新签发的编号为 `r_` 加 12 个随机字符，总长 14。例如 `r_7m4k9q2x6p8t`；示例不是可使用的凭据。
- 字符集合为 `0123456789abcdefghjkmnpqrstvwxyz`，使用系统安全随机源。字符区分大小写，不做别名转换或自动纠错。
- 字段名仍为 `readToken`，编号只用于查找服务端持久读取记录，不包含文件、版本或范围的编码信息。调用者必须复制工具返回的完整值，不能自行生成、截短或推断编号。
- 随机空间为 60 位，低于原 UUID 的约 122 位；这是已确认的短编号取舍。保留校验条件不代表保留原有防猜强度。
- 不新增顺序计数器或第二套编号映射。

## 签发与持久化

1. 同一会话、同一文件版本的续读复用有效凭据，并仅合并实际交付的范围。
2. 首次读取、版本变化或过期后读取，以及成功编辑后的续签，签发新短编号。
3. 新记录先写入同目录临时 JSON 并同步内容，再以独占硬链接原子发布。目标已存在时重新生成编号，不覆盖原记录，不向调用者返回半写入的记录。
4. 已有凭据的成功续读仍原子更新原记录；记录成功保存后更新现有会话/文件索引。
5. 沿用当前状态根与索引布局，跨 helper 进程和 MCP 重启可以读取有效凭据。新旧凭据都按现有期限回收，不引入常驻程序。

## 保留的校验

- 必须存在完整匹配的已签发记录；编号不正确或记录不可用时返回 `READ_REQUIRED`。
- 继续核对 `sessionId` 与规范文件路径；串用凭据仍为 `READ_SCOPE_MISMATCH`。
- 继续核对文件身份、版本与实际交付范围，未读内容不会因编号变短获得编辑资格。
- 保留连续 3 天无成功相关操作即过期的规则，失败和查询不续期，过期后不复活旧范围。
- 保留同会话不重叠编辑的最近 10 分钟、128 次提交、4 MiB 有界变更链及冲突拒绝规则。
- 编辑已提交但续签失败时，继续返回 `written=true`、`rereadRequired=true`、`readToken=null`；不得把它当作未提交重复编辑。

## 升级兼容

新版本同时接受 `r_` 短编号和原 32 位小写十六进制编号，不要求批量迁移已有记录。同版本的有效旧凭据可以继续续读；成功编辑后换发短编号。清理和编辑历史维护同时识别两种格式。

兼容的是旧凭据记录。旧执行器本身不识别短编号，因此升级时应重启共用同一绑定的旧版 MCP 进程，避免混用执行器版本。

## 验证与现场边界

- 契约测试覆盖短编号格式、同版本复用、成功编辑续签与跨 helper 进程续用。
- 强制随机源产生碰撞时，另一文件的原凭据继续有效；并发独占发布只产生一个完整记录，落败者不能覆盖胜者。
- 错填、截短、大小写改写、路径穿越、跨文件和跨会话请求保持拒绝。
- 旧 32 位凭据可续读、编辑并换发短编号；新旧凭据及其索引均可按期回收。
- 原有文件操作、并行编辑、有效期、清理与宿主回归必须通过，日志留在本次工作树的 `.artifacts/read-token/`。
- GLM 的复制错误是否下降，需要以真实客户端同类任务对比确认；本机契约测试不替代用户人工验收。
