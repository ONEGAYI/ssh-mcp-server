# 大文件启动与恢复改进规格

状态：2026-10-08，四项改进及追加的 setup 连接列表均已授权并实施，本机回归通过；现场为另一台机器的 ZCode + 2.2.0，现场网络表现尚未复测。

## 目标与用户故事

1. 作为使用远端绑定的 Agent，我希望启动传输后立即拿到持久编号，以便大文件摘要计算和传输不占据 MCP 等待窗口。
2. 作为恢复对话的 Agent，我希望在不知道编号时离线列出本会话传输，以便接回原传输而不创建副本。
3. 作为处理结果的 Agent，我希望错误和终态结果明确说明后续操作，以便续传或确认结果。
4. 作为 Windows 用户，我希望路径拒绝和打包指引解释正确的路径用法，以便在保护范围内准备文件。
5. 作为恢复中断的 Agent，我希望服务退出后仍能查询和恢复原传输，并且等待和取消遵循既有提交保护。

## 接口与实施决策

- 新增 `remote_transfer_pending(sessionId, offset)`，每页 50 条；仅查本机登记、按会话隔离、返回 `nextOffset` 和损坏登记计数。不触发在线维护。旧 `remote_pending` 同样避免在线维护。
- MCP 错误返回已有或请求携带的 `transferId`；不暴露配置或认证信息。
- 上传、下载终态结果带 `acknowledgementRequired` 和明确的确认操作。`unknown` 与运行中状态不能确认。只读状态查询不隐式确认。
- 本机路径仍受 `localRoot` / `allowedLocalPaths` 与真实路径检查约束；拒绝消息说明允许根目录和配置项，不默认放开临时目录。
- MCP `start` 先做本机参数、路径和源/目标元数据检查，生成并持久化本机编号，然后启动独立 Node 进程，返回 `preparing`。摘要计算、SSH 安装/连接、远端登记及数据循环均由该进程承担。
- 本机编号作为远端登记的指定编号。远端同编号重放须核对会话和登记意图，返回原记录；登记响应丢失后重放不产生另一传输。旧调用未指定编号时继续由远端分配。
- 新启动记录必须能被列表、恢复钩子和绑定移除检查识别。尚未获得远端总大小的下载明确标记总大小未知，不把零进度说成已完成。
- 同一新传输的执行权由操作系统 IPC 端点独占；Windows 命名管道与 Linux 抽象 socket 会随进程退出释放，登记 PID / 令牌仅用于查询。CLI `transfer wait` 观察驱动并在进程退出后接回同一编号；显式取消须在驱动停止后沿原取消/提交核对契约执行。不得因超时猜测取消成功。
- 原有同步 `upload/download/resume` 驱动和旧记录保持兼容；CLI 原有同步 `transfer start` 保留，供 ZCode 原生后台 Shell 使用。新 MCP 启动后的 `resume` 只负责接回独立驱动。
- CLI wait / resume 遇到 `unknown` 结束等待，返回非零退出码且 `acknowledgementRequired=false`，不提示重新接回；该状态须人工核实。本机到期维护沿 IPC 判断执行权，遗留 PID 不阻塞回收。
- `remote_help` / README / usage 说明后台 `transfer start`、同编号 `transfer wait`、编号丢失后的列表恢复及处理后 `ack`。Windows GNU tar 使用 MSYS 路径或 `--force-local`。

## 验收标准

- MCP 启动不执行整文件摘要或 SSH 操作；网络不可达时仍能迅速返回可查询编号。
- 丢失启动返回或停止 MCP 服务后，列表和恢复钩子均找回同一编号；后台驱动不依赖 MCP 内存 Promise。
- 登记返回丢失、驱动中断和重挂接保持编号、源版本及分块校验；上传与下载各有覆盖。
- 服务层错误编号穿过 MCP；终态处理后显式确认才从 pending 消失。
- 并发等待不产生两个接收写入者；运行中取消不会复活或回滚正式文件。
- 旧传输、会话隔离、路径保护、未知状态、清理及移除检查的回归测试通过。

## 范围边界

### 用户追加：setup 连接列表

setup 过去只在 configure 的缺项响应中返回预存 JSON 连接名，没有显式列表动作。新增 `remote_setup(action="list_connections", sshConfigFile?)`，只读启动 `--config-file` 或调用指定的 SSH MCP JSON，返回 `connections_listed` 与连接名；不要求工程目录，不写文件，不连接 SSH，不回传主机或认证字段。缺少路径时只询问 JSON 文件路径；工具说明指明入口及它与 OpenSSH `.ssh/config` 的区别。协议测试覆盖发现、路径选择、错误、不泄露认证及无写入。

### 保留边界

不修改远端 Windows 支持、不增加 GUI、不自动确认、不放宽目录边界、不另建常驻服务或安装系统服务。本轮不发布版本或自动合并 PR；真实 ZCode / CentOS 7 验收仍由用户进行。

独立驱动支持 Windows / Linux 本机（Linux Node 20.8+），其他本机平台继续用同步 CLI 的后台入口。启动异常写回本机登记与 driver.log，不以持续 preparing 隐藏错误。
