# 通过 SSH 操作旧版 Linux 的 Agent 工作环境

本项目在本机运行 Agent，通过 SSH 操作旧版 Linux 服务器。用户已确认首版规格与实施计划，当前进行阶段 0 验证；未验证接入仍需通过证据验收。

## 用户已提供的背景与目标

- 目标服务器为 CentOS 7；用户反馈 ZCode / Codex 的远程连接无法支持，目前只能基本 SSH 连通。尚未获取远端运行环境或复现相关连接失败。
- 希望改造 `@fangjunjie/ssh-mcp-server`，获得接近在服务器上原生运行 Agent 的体验。
- 第一轮 Q1 已确认：首要验收客户端为内网 Win11 上的 ZCode；实际开发环境位于该 Win11 可经 SSH 连接的 CentOS 7。用户希望 ZCode 在 Windows 运行，通过 MCP 近似原生操作 Linux 开发环境。
- 第一轮 Q2 已确认：远端就是 Linux；远端不能联网、没有 root 权限，必须兼容旧版 glibc。用户表示其他方面应该没有限制，因此可考虑用户目录内离线部署辅助程序；具体运行时与部署形式未定。Win11 的联网能力尚未说明。
- 第一轮 Q3 已确认：命令应在后台执行，不阻塞主 Agent；完成后主动送达 Agent 并触发下一步。只返回任务编号、依赖 Agent 以后主动查询不满足目标，用户担忧上下文遗忘导致任务失去跟进。
- 用户补充确认：ZCode 原生后台 Shell 也会在完成时回传并触发 Agent，优先利用这一机制，无需为等待额外运行子代理。接入流程必须让 ZCode Agent 以后台方式调用 Shell 工具；尚未在目标版本实测。
- 第一轮 Q4 已确认：接受专用 MCP 文件工具的读后写保护范围，包含修改、整文件覆盖、上传覆盖、新建以及删除/移动的对应检查。使用提示词等方式引导 Agent 优先使用这些工具操作文件，不要求拦截任意 Shell 写入，正常开发命令保留自由度。
- 第一轮 Q5 已确认：SSH 断线或本机客户端退出后，远端任务继续执行，重连后恢复跟进。服务器自身重启后的自动重跑不纳入本轮推荐范围。
- 第一轮 Q6 已确认：典型操作为 `make build`、使用 `rg` 搜索大仓库；首版无需交互式输入，按正常 Agent Shell 工具的体验设计。用户要求评估交互式复杂度与延后实现的改动量，尚未授权实施交互式功能。具体耗时与完整工具链尚未提供；Codex 不作为首要验收对象。
- 用户在交互式评估后回复“可以”：采用首版非交互、任务与连接分离、等待与执行分离、日志增量读取及执行方式可扩展的方向。具体接口与资源默认值在本轮规格中提出，不能当作此前用户逐项确认的事实。
- 期望能力包括远端读写、后台执行命令、结束自动提醒，以及要求先读取且中途未变动的写入保护。
- 用户授权建立独立工作目录，并使用 grill-with-docs 对齐需求。设计文档放在本项目 `docs/` 下，不散落在 `D:\CODE\Project` 工程集总根。
- 用户已授权实施。当前先使用同处互联网环境的 Windows 与 CentOS 7 VM 做测试；Windows 就是本会话所在机器，ZCode 版本为 3.11.2。使用现有原版 SSH MCP 的 CentOS-EDA VM 连接，最终内网目标的离线、无 root、旧 glibc 要求不变。
- 用户已确认重启后的恢复触发点：继续原对话时，由恢复钩子提供挂起任务与未处理结果，Agent 重新挂接后台等待；不要求仅启动 ZCode 就立即唤醒原对话，也不要求用户记任务编号。

## 大文件扩展访谈（2026-09-12）

- 用户要求逐点确认并及时记录，未确认方案不视为实施要求。2026-09-13 调整访谈节奏：每轮最多提出三个互不依赖的问题，以加快讨论；依赖未决答案的问题留待后续轮次。
- 已确认：取消每次读写的全文哈希，保留文件元数据变更检查与实际已读区间保护。replace 仍要求全文唯一原文匹配；重复时读取更多上下文、扩大匹配片段，不能自动选第一处或全部替换。详见 [ADR 0006](../adr/0006-large-file-version-checks.md)。本项尚未实施。
- 用户关注约 200 MB 网表的处理成本，希望搜索与修改在存放文件的 CentOS 7 服务器上执行，避免为局部操作把全文传回本机；内存开销通过远端分块处理控制。
- 已确认：搜索默认不按 `.gitignore` 排除文件，提供开关允许调用方启用该过滤，避免生成网表因忽略规则而默认不可检索。默认包含点开头的文件和目录，但排除 `.git/` 内部数据，提供关闭隐藏文件搜索的开关。尚未实施；其他忽略文件规则留待后续确定。
- 已确认内容搜索后端顺序：远端 Linux 为 rg → GNU grep → Python 分块搜索；远端 Windows 为 rg → GNU grep → Python 分块搜索 → Windows PowerShell Select-String。所有后端先检测实际可用性，不假定远端已有 Python、Node.js 或 GNU grep；本机运行 Node.js 不代表远端安装了 Node.js。
- 上述顺序是综合性能与可用性的选择策略，不是固定性能排名。搜索在远端执行，只回传有界结果，并遵守已确认的忽略规则选择。文件名查找需另行适配。本轮优先完成 CentOS 7；远端 Windows 的完整支持另行实施，已按用户要求创建 [Issue #4](https://github.com/ONEGAYI/ssh-mcp-server/issues/4)，保留既定 Windows 搜索后端顺序，当前 Linux/Python helper 不因此视为已支持 Windows。
- 已确认：移除 remote_move、remote_delete、remote_mkdir、remote_rmdir，统一通过远端 Shell 操作。用户接受移动、删除不再由专用工具强制检查已读凭据和文件版本。详见 [ADR 0007](../adr/0007-file-management-through-shell.md)，尚未实施。
- 已确认：整体覆盖已有文件（包括上传替换）不要求模型读完旧文件全文。默认拒绝覆盖；工具调用须显式声明覆盖并绑定检查过的目标版本，提交前发现目标变化则拒绝。局部 replace 的已读区间要求不变。详见 [ADR 0008](../adr/0008-explicit-version-bound-overwrite.md)，尚未实施。
- 已确认：本轮上传与下载均支持断点续传；重连后检查源版本与已传分块，再继续原传输，上传完整校验后才提交正式目标。小型状态分别存放在两侧工作区状态目录的 transfers/ 下，接收临时文件放在目标同目录。详见 [ADR 0009](../adr/0009-resumable-file-transfers.md)，尚未实施。
- 用户明确要求：状态和临时文件不得无节制、无限期堆积。后续逐点确定生命周期、自动清理机制与空间控制，覆盖现有任务状态、日志、读取凭据、锁、helper 版本及遗留临时文件，也覆盖新增传输记录与临时数据。
- 已确认：已完成且结果已确认的完整任务日志，从结果确认起默认保留 3 天。采用启动、重连、操作时触发的懒清理，加 MCP 在线期间默认每小时一轮的低频维护；两类触发需节流与互斥。用户接受停用或断连期间延后至下次连接清理，不额外部署远端常驻清理或独立定时任务。详见 [ADR 0010](../adr/0010-state-cleanup-lifecycle.md)，尚未实施；其他数据期限与配额待定。
- 已确认：已中断且无进程占用的传输临时数据，从最后一次实际传输进展起保留 3 天；查询状态不延长期限，到期清理后明确提示续传已过期、需重新传输。详见 ADR 0010，尚未实施。
- 已确认：已完成且结果已确认的小型任务及传输记录从确认起保留 30 天，到期清理；过期旧请求必须拒绝，不能因记录已删除而重新执行命令或再次覆盖。实施前须配套建立不依赖永久逐条记录的过期请求拒绝机制，详见 ADR 0010，尚未实施。
- 已确认：已结束但一直未被 Agent 确认的任务结果，从任务结束起保留 30 天，到期清理完整日志及结果详情，之后明确提示结果过期、旧输出无法恢复；旧请求仍拒绝重跑。运行中或结束状态未知的任务不套用此期限，详见 ADR 0010，尚未实施。
- 已确认：readToken 连续 3 天没有成功的相关读取或编辑就过期回收，成功的相关操作续期；文件外部变化仍立即使旧凭据失效。过期后只需重新读取拟修改片段，不要求全文读取。详见 ADR 0010，尚未实施。
- 已确认：普通临时文件在操作成功或明确失败后立即清理不再需要的部分；崩溃残留在下一轮维护中确认归属、无进程占用且不再用于恢复后清理，不额外保留数天。断点续传数据仍按 3 天规则处理，提交结果不明确的文件先核对。详见 ADR 0010，尚未实施。
- 已确认：远端 helper 只保留当前版本及仍被活动任务或连接依赖的版本；其余版本确认无依赖后在下一轮维护清理。回退时从对应本机离线包重新部署，不永久保留远端历史副本。详见 ADR 0010，尚未实施。
- 已确认：锁文件改为固定数量、按目标标识分配并循环复用，避免随历史操作数量增长；接受不同目标偶尔共用锁而额外排队。具体数量、统一加锁顺序及兼容迁移见后续规格，详见 ADR 0010，尚未实施。
- 已确认：空间额度不足时先回收已过期且可安全清理的数据，仍不足就拒绝新增占用并提示原因，不提前删除未到期续传数据、未确认结果或正在使用的文件。任务和传输启动前检查并预留额度，详见 ADR 0010，尚未实施。
- 已确认：每个工作区本机和远端各自默认上限 10 GiB，可配置调整；状态、日志、辅助程序和本服务管理的临时数据均计入，包括目标目录旁的续传文件。正式工程文件和提交后的目标文件不计入，多工作区额度独立并会累加。详见 ADR 0010，尚未实施。
- 已确认：本轮支持已有绑定的二次配置，读取现有值、只更新指定字段并保留其余配置。额度、保留期限、搜索选项等普通策略保存后无需重启，在下一次操作或维护周期读取新值，不打断正在执行的任务或传输。保留期限变更不追溯已有记录，已有记录保持原到期时间，新记录采用新期限。更换服务器或状态目录本轮通过新建绑定处理，保留旧绑定完成旧任务和清理状态，不做自动迁移。详见 [ADR 0011](../adr/0011-binding-reconfiguration.md)，尚未实施。
- 已确认：取消 16 MiB 门槛，不另设统一文件体积上限；读取和搜索受返回量及执行预算约束，写入和传输还受空间额度与实际磁盘空间约束。详见 ADR 0006，尚未实施。
- 已确认：完整上传下载采用分块校验支持续传，完成时核对整文件 SHA-256，校验在两端计算，不额外通过网络传输一遍全文。详见 ADR 0009，尚未实施。
- 已确认：主动取消传输，在确认已停止后立即删除未提交且不再使用的临时数据，不保留 3 天；已提交的正式文件不回滚。意外中断继续适用 3 天期限。详见 ADR 0009，尚未实施。
- 已确认：耗时上传下载支持后台执行、进度查询和完成回传；断线后跟进同一传输，不另起一份。具体后台接入留待规格明确，详见 ADR 0009，尚未实施。
- 已确认：空间概览由现有 remote_workspace 的可选参数按需返回，默认不附加，不新增 MCP 工具；仅返回两端用量、预留额度、分类统计和最近清理摘要，不逐条列出状态文件。自动统计和维护不调用模型，避免持续增加对话上下文。详见 ADR 0010，尚未实施。

大文件扩展补充确认：任务或传输结果未知时，从首次进入未知状态起默认保留 30 天；到期清掉结果、诊断及恢复记录，停止自动恢复，提示人工核对，不能因为结果未知无限保留。过期旧请求仍拒绝重跑，正式文件不删除；临时数据确认无占用后回收，清理记录不得使临时资源失去管理。详见 ADR 0010，尚未实施。

## 领域术语

**本机客户端**：本需求中特指运行于用户内网 Win11 的 ZCode。远端命令执行位置与客户端运行位置不同。

**目标服务器**：用户只能通过 SSH 访问的 CentOS 7 Linux 服务器，承载实际文件和命令执行。

**写入保护**：MCP 专用文件工具执行的修改前读取要求与文件版本检查，防止误覆盖，不覆盖任意 Shell 命令。已实现规则见 contracts.md；已接受、尚未实施的版本检查调整见 ADR 0006，移动与删除工具的保护范围调整见 ADR 0007。

**唯一原文匹配**：oldText 在整个目标文件中恰好出现一次，且完整匹配片段已交付给当前会话；多处出现时需要扩大上下文后重试。

**显式整体覆盖**：调用方明确要求以新内容替换已检查版本的目标文件；该操作不以模型完整已读为前提，目标版本观察也不授予已读区间。

**完成提醒**：远端后台命令结束后，结果主动送达所属 Agent 对话并触发下一步处理。只通知人类或要求 Agent 记住任务编号后主动查询，都不足以满足用户目标。

**任务编号**：远端后台命令的查找标识。编号可以用于查询和恢复，但任务跟进不能只依赖模型上下文记忆。

**后台等待程序**：拟由 ZCode 原生后台 Shell 启动的本机程序，等待远端任务终结后返回结果，使 ZCode 通过自身后台机制继续主对话。具体接口尚未定案。

**远端任务恢复**：SSH 重连或本机客户端重新启动后，重新识别原有任务、取得日志和状态，并恢复结果跟进；不等同于重新执行原命令。

**绑定移除**：remote_setup 的 remove 动作，解除一个绑定在本机项目的全部接入痕迹（profile、生成的连接配置、MCP 条目与恢复钩子、本地状态目录）；不连接远端，远端状态目录仅报告路径由用户自行处理。尚未实施。

**按需指引**：由 remote_help 工具返回的完整工作区使用指引，取代 configure 落盘的三个 markdown 文档；文本与代码版本一致，不落盘、无内容匹配删除与历史版本问题。工具已实施（PR #34）；落盘文档退役与存量迁移清理属 #31，尚未实施。
