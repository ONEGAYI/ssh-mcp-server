# 通过 SSH 操作旧版 Linux 的 Agent 工作环境

本项目在本机运行 Agent，通过 SSH 操作旧版 Linux 服务器。用户已确认首版规格与实施计划，当前进行阶段 0 验证；未验证接入仍需通过证据验收。

## 用户已提供的背景与目标

- 目标服务器为 CentOS 7；用户反馈 ZCode / Codex 的远程连接无法支持，目前只能基本 SSH 连通。尚未获取远端运行环境或复现相关连接失败。
- 希望改造 `@fangjunjie/ssh-mcp-server`，获得接近在服务器上原生运行 Agent 的体验。
- 第一轮 Q1 已确认：首要验收客户端为内网 Win11 上的 ZCode；实际开发环境位于该 Win11 可经 SSH 连接的 CentOS 7。用户希望 ZCode 在 Windows 运行，通过 MCP 近似原生操作 Linux 开发环境。
- 第一轮 Q2 已确认：远端就是 Linux；远端不能联网、没有 root 权限，必须兼容旧版 glibc。用户表示其他方面应该没有限制，因此可考虑用户目录内离线部署辅助程序；具体运行时与部署形式未定。Win11 的联网能力尚未说明。
- 第一轮 Q3 已确认：命令应在后台执行，不阻塞主 Agent；完成后主动送达 Agent 并触发下一步。只返回任务编号、依赖 Agent 以后主动查询不满足目标，用户担忧上下文遗忘导致任务失去跟进。
- 用户补充确认：ZCode 原生后台 Shell 也会在完成时回传并触发 Agent，优先利用这一机制，无需为等待额外运行子代理。接入流程必须让 ZCode Agent 以后台方式调用 Shell 工具；尚未在目标版本实测。
- 第一轮 Q4 已确认：接受专用 MCP 文件工具的读后写保护范围，包含修改、整文件覆盖、上传覆盖、新建以及删除/移动的对应检查。使用提示词等方式引导 Agent 优先使用这些工具操作文件，不要求拦截任意 Shell 写入，正常开发命令保留自由度。
- 第一轮 Q5 已确认：SSH 断线或本机客户端退出后，远端任务继续执行，重连后恢复跟进。服务器自身重启后的自动重跑不纳入本轮推荐范围。
- 第一轮 Q6 已确认：典型操作为 `make build`、使用 `rg` 搜索大仓库；首版无需交互式输入，按正常 Agent Shell 工具的体验设计。用户要求评估交互式复杂度与延后实现的改动量，尚未授权实施交互式功能。具体耗时与完整工具链尚未提供；Codex 不作为首要验收对象。
- 用户在交互式评估后回复“可以”：采用首版非交互、任务与连接分离、等待与执行分离、日志增量读取及执行方式可扩展的方向。具体接口与资源默认值在本轮规格中提出，不能当作此前用户逐项确认的事实。
- 期望能力包括远端读写、后台执行命令、结束自动提醒，以及要求先读取且中途未变动的写入保护。
- 用户授权建立独立工作目录，并使用 grill-with-docs 对齐需求。设计文档放在本项目 `docs/` 下，不散落在 `D:\CODE\Project` 工程集总根。
- 用户已授权实施。当前先使用同处互联网环境的 Windows 与 CentOS 7 VM 做测试；Windows 就是本会话所在机器，ZCode 版本为 3.11.2。使用现有原版 SSH MCP 的 CentOS-EDA VM 连接，最终内网目标的离线、无 root、旧 glibc 要求不变。
- 用户已确认重启后的恢复触发点：继续原对话时，由恢复钩子提供挂起任务与未处理结果，Agent 重新挂接后台等待；不要求仅启动 ZCode 就立即唤醒原对话，也不要求用户记任务编号。

## 领域术语

**本机客户端**：本需求中特指运行于用户内网 Win11 的 ZCode。远端命令执行位置与客户端运行位置不同。

**目标服务器**：用户只能通过 SSH 访问的 CentOS 7 Linux 服务器，承载实际文件和命令执行。

**写入保护**：MCP 专用文件工具执行的修改前读取要求与文件版本检查，防止误覆盖。范围已确认，不覆盖任意 Shell 命令；部分读取、并发保证与“变过又恢复”的细节仍待明确。

**完成提醒**：远端后台命令结束后，结果主动送达所属 Agent 对话并触发下一步处理。只通知人类或要求 Agent 记住任务编号后主动查询，都不足以满足用户目标。

**任务编号**：远端后台命令的查找标识。编号可以用于查询和恢复，但任务跟进不能只依赖模型上下文记忆。

**后台等待程序**：拟由 ZCode 原生后台 Shell 启动的本机程序，等待远端任务终结后返回结果，使 ZCode 通过自身后台机制继续主对话。具体接口尚未定案。

**远端任务恢复**：SSH 重连或本机客户端重新启动后，重新识别原有任务、取得日志和状态，并恢复结果跟进；不等同于重新执行原命令。
