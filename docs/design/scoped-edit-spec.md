# 已读范围全部替换与同会话并行编辑

2026-10-10 用户通过需求访谈确认并授权实施，决策见 [ADR 0013](../adr/0013-scoped-replace-all-and-concurrent-edits.md)。本规格补充现有精确编辑契约；用户人工验收仍待完成。

## 目标与接口

- 每条 `remote_edit.edits` 项新增布尔参数 `replace_all`，默认 `false`。一次调用仍接收 1–100 项，可以混合两种模式。
- 默认模式保留 `oldText` 在整个读取版本中恰好一次的规则。`replace_all=true` 仅在该读取凭据的已读区间内匹配；完整命中必须被已读范围覆盖，跨未读间隔的命中不纳入替换。
- 全部替换在每个已读区间内从左到右选择不重叠命中。未读内容不获得编辑资格，不为计数而逐个搜索未读内容中的命中。
- 任一项没有合格匹配、默认模式歧义、匹配未读或批内区间重叠时，整次调用不提交。保留 UTF-8、BOM、CRLF、权限与属组保护，普通模式原有错误代码保持兼容。

## 范围报告与预算

- 成功结果继续返回 `editsApplied`、`written`、新 `readToken` 与 `version`。新增 `beforeVersion` 与按输入顺序排列的 `editResults`。
- 每项结果包含 `scope`（`file` 或 `readRanges`）、`replacementsApplied`、`ranges` 和 `rangesTruncated`。范围是实际提交前版本中的 UTF-8 字节区间，左闭右开；`beforeVersion` 标明其坐标版本。
- 范围列表在整个请求中最多展示 128 个区间；截断时计数仍准确。`scope=readRanges` 不能被表述成已经完成全文件全部替换。
- 每次请求最多规划 65,536 个实际替换区间；超出时返回 `EDIT_LIMIT`，提示缩小替换目标，且不提交。该预算限制匹配计划的内存，不限制文件大小。
- 继续按 256 KiB 流式校验和扫描文件；重写经过同目录临时文件与现有资源账本，全部校验后原子提交。

## 旧凭据与并行提交

- 调用方可以并行发出请求，服务端沿用文件锁依次提交。
- 本轮仅跟踪同一 `sessionId`、同一文件经 `remote_edit` 成功提交的修改。读取凭据仍校验会话、规范路径、到期时间与原已读范围；不同会话、Shell、write/upload 等其他写入不能进入可合并链。
- 变更记录保存提交前后版本、提交时间、原始匹配文本与修改区间及新字节数。原文按编辑项保存一次，多个命中共享原文；不保存整个文件副本。
- 旧版本请求必须有连续记录连接到当前实际版本。利用记录和当前文件的未修改片段流式还原读取版本，在该版本中定位目标，随后逐次映射到当前坐标。
- 目标与任一中间修改区间重叠时返回 `FILE_CONFLICT` 并要求重读，即使当前仍能找到相同原文或两个调用想写相同结果。前方不重叠的增删只移动目标坐标。
- 成功后按当前会话最新的合法已读范围续签凭据，保留未读间隔；结果返回 `rebased`，标明是否使用了变更链。

## 持久化、期限与失败

- 记录保存在现有会话/文件读取索引内，与凭据续签一起原子更新索引；跨 helper 进程与 MCP 重启仍可读取。每个索引只保留最近 10 分钟、最多 128 次提交、最多 4 MiB 的历史。
- 读、编辑和现有维护轮裁剪过期历史；超过数量或体积预算时淘汰最旧记录。单次记录过大时放弃该次追踪并断开旧链，不阻止已通过校验的编辑。
- 成功结果以 `concurrentReplayAvailable` 报告本次修改是否进入可追踪历史。历史丢失、超期、超额或版本断链时，旧凭据返回 `FILE_CONFLICT` 并要求重新读取；当前版本的有效凭据继续可用。
- 保留读取凭据原有 3 天闲置期限，不复活过期凭据。维护裁剪历史不续期凭据，也不新增远端常驻程序。
- 写入已经提交但续签或索引保存失败时，继续明确报告 `written=true`、`rereadRequired=true`；没有完整记录便不允许旧凭据跨过该次写入。提交失败不留下可用的虚假变更链。

## 验收

1. 重复原文在两段已读范围中全部替换，未读命中保持原样；默认模式仍拒绝多匹配，混合模式一次提交。
2. 跨分块边界、UTF-8/BOM/CRLF、删除及变长替换保持正确；范围报告与计划预算有界，拒绝没有部分写入。
3. 同一旧凭据发起真正并发、目标不重叠的多个请求全部成功，包括前方增删导致后方移位。
4. 同一目标或包含该目标的全部替换发生重叠时整次拒绝；其他请求新引入的同文本不能被误选成原目标。
5. 不同会话、Shell、整文件覆盖、过期凭据、历史超期/超额/丢失及提交后存储失败保持拒绝或明确恢复指引。
6. MCP schema 暴露并保留每项开关；Node 与 Python 全量回归通过。真实客户端与 CentOS 7 的人工验收另行记录。
