# 首版实施与验收计划

状态：用户已授权实施与分批本地提交。阶段 0–3 的核心实现和自动验证已完成，阶段 4 正在整理离线预览交付与人工验收。测试使用当前 Windows（ZCode 3.11.2）与联网的 CentOS 7 VM，通过已配置的原版 SSH MCP 访问；最终兼容约束不变。所有阶段都在当前独立项目内进行，交付通过 PR 留痕；未获推送授权前仅本地工作。

## 阶段 0：验证兼容条件与恢复回传

**目的：先证明最影响整套方案的链路，而不是先堆文件工具。**

- 核实目标 ZCode 版本与原生后台 Shell：主回合结束后，命令结束能否回传并启动下一轮。
- 验证真实对话标识获取、后台等待登记、本机退出/重启后恢复同一任务，以及未确认完成事件的补发与去重。
- 在获得目标连接条件后，只读探测 CentOS 7 的运行时、基础命令、exec/SFTP 能力与工作区文件系统。不修改系统环境，不假设当前对话所在机器就是目标 Win11。
- 用受控的测试任务验证远端脱离 SSH 存活、进程身份核对、结束记录和增量日志；验证所需辅助能力能以离线、无 root 方式部署。
- 固定远端依赖表及 ZCode 接入方案。必要时用兼容测试环境验证；目标机验收单独列出，不能用模拟结果替代。

产物：探测报告、最小可重复验证、确定的适配接口与通过/失败证据。若 ZCode 恢复后无法自动重新登记等待，则明确缺口并修订接入方案，不继续宣称完整目标已可实现。

## 阶段 1：可靠命令主链路

- 复用上游连接配置，建立任务核心和薄的本机命令入口。
- 实现远端任务身份、启动去重、独立执行、日志与退出记录。
- 支持显式目录/环境、并行任务、有界日志返回、等待与执行超时分离、显式取消。
- 接通阶段 0 验证过的 ZCode 原生后台 Shell 正常完成回传。

验收：`make build` 与大输出搜索不阻塞主对话；完成结果能继续原对话；命令非零退出、无搜索匹配和 SSH 错误被正确区分。

## 阶段 2：断线及重启恢复

- 完成本机跟进记录、退避重连、原任务状态核对与日志游标恢复。
- 完成 ZCode 恢复后的等待登记、未处理结果补发、事件去重及不可恢复原对话的处理。
- 验证启动时断线、远端已启动但本机未收到确认、完成后客户端尚未消费等窗口。

验收：断线和退出不杀任务，恢复后不重复运行命令；结果主动回到可恢复的原对话。只找回日志不算通过。

## 阶段 3：受保护文件工具

- 实现工程上下文、目录/路径查找、按行读取、内容搜索与分段返回。
- 实现真实读取凭据、版本检查、精确编辑、覆盖写与上传保护，以及不存在才创建。
- 实现单文件删除/移动和下载，明确链接、编码、跨文件系统与目录操作边界。
- 覆盖开发模式中所有专用覆盖写入口，提供冲突后重新读取的指引。

验收：未读拒绝、读取后冲突拒绝、局部读取范围正确、上传不能绕过覆盖保护；中文/空格路径与换行得到保留。普通开发命令保持可用。

## 阶段 4：离线交付与端到端验收

- 打包本机 MCP 与命令入口、版本化远端辅助程序和操作指引，记录安装与升级方法。
- 配套提示词/技能说明远端工程与本机目录区别、优先文件工具，以及必须用 ZCode 原生后台方式调用命令入口。
- 完成日志配额与清理、并行隔离、旧模式兼容和旧系统部署验证。
- 用用户实际 Win11/ZCode → CentOS 7 环境跑完整验收流程，再提交供人类审阅。

## 测试策略

沿用 Node.js 内置测试框架，功能实施先写行为测试，再实现。现有 `integration.test.js` 主要验证配置传递；已有 SSH 测试使用模拟 channel，均不能独立证明远端断线存活。

优先从 MCP/CLI 公共接口验证行为。基础 SSH 失败注入复用现有测试设施；涉及远端进程、文件提交和断线的测试必须增加真实 Linux/SSH 测试层，避免为每个内部方法设计模拟接口。

| 验收类别 | 必须覆盖的行为 |
|---|---|
| 文件保护 | 未读、旧版本、部分读取、歧义替换、两写入者冲突、目标创建竞争、失败后原内容保留 |
| 文件保真 | UTF-8/BOM、LF/CRLF、末尾换行、空文件、中文/空格/特殊字符路径、不支持对象明确报错 |
| 任务执行 | 并行隔离、不同 cwd/env、空输出、大输出、非零退出、无匹配、显式执行上限 |
| 任务恢复 | 启动确认丢失、SSH 断开、MCP 重启、等待进程退出、ZCode 重启、远端记录不完整 |
| 取消 | 子进程、PID 复用防护、自然退出竞争、重复取消、信号未生效不能假报成功 |
| 完成回传 | 主回合结束后的唤醒、恢复原对话、重复事件、消费确认前退出、原对话已删除 |
| 兼容部署 | 无 root、无外网、目标 glibc、SFTP/exec 探测、基础工具缺失、旧模式保持原契约 |

变更后执行上游构建与测试。Windows 上先核实既有测试入口是否正确处理工作目录，若失败先定位，不将未运行的检查算作通过。文档阶段仅进行差异与链接检查，不宣称运行过产品测试。
