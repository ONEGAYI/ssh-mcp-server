# 摘要计算前持久登记传输，并由独立本机进程驱动

2026-10-08，用户授权实施大文件启动、恢复入口、操作提示与后台指引四项改进。

## 背景

ZCode 现场的 MCP 调用在约 30 秒后结束等待，而 2.2.0 的 start 同步计算全文摘要、登记并驱动数据，默认驱动预算为 55 秒。预算从登记后开始，且在途 SSH 交换可越过预算。调用结果丢失后，原传输仍可能存在，但 MCP 缺少无需编号的发现入口。

## 决定

- MCP start 先进行本机边界与元数据检查，持久化本机编号和启动意图，再启动独立 Node 进程；返回 preparing，不等待全文摘要或 SSH。
- 远端登记接受指定编号；同编号、同会话及同意图重放返回原记录。下载重放保留原源版本和摘要，不能把变更后的远端内容绑定到旧编号。
- 指定登记携带不可自动续期的首次登记有效期。已回收登记留下有期限的小型凭据，旧请求不能在结果回收后重新创建；凭据到期沿现有有界维护回收。
- 驱动执行权由本机操作系统的 IPC 端点独占保证：Windows 使用命名管道，Linux 使用抽象 Unix socket；进程退出时操作系统释放端点。PID / 独立令牌记录用于查询与诊断，不承担死锁接管。CLI wait 观察或重新接回原驱动；同一下载不由多个等待器分别写入。MCP 退出不结束独立驱动，本机重启或驱动退出后按原编号恢复。[Node IPC 文档](https://nodejs.org/api/net.html#ipc-support)
- 网络中断保留可恢复状态，等待器按需重新接回；不靠常驻守护进程、系统服务或内存 Promise 宣称持久完成。
- 新 MCP 取消先保存请求，驱动核实后才报告终态；已提交正式文件和 unknown 边界遵循既有契约。读取终态不自动 ack。
- 本机到期维护也依据 IPC 判断驱动存活，不能因为遗留 PID 被复用而长期保留过期记录。CLI wait / resume 遇到 unknown 返回非成功结果、结束等待且不要求 ack；正式文件发布情况须人工核实。
- 旧同步 CLI 和旧传输记录保留兼容，通过 ZCode 原生后台 Shell 使用，软 budget 不再描述为客户端调用时限。

## 验证与边界

本机测试覆盖独立进程、MCP 退出、上传/下载摘要一致、丢失登记返回、驱动被终止、并发等待、取消、校验阶段断线与显式确认。SSH 在测试边界模拟；Python 登记与回收在 WSL 使用真实 helper 验证。另一台机器上的真实 ZCode / CentOS 7 传输尚待用户验收。

快速 MCP start 当前支持 Windows / Linux 本机；Linux 需要支持抽象 socket 的 Node 20.8+（分发自带当前 Node）。其他本机平台使用同步 CLI 后台入口，不宣称新独立驱动已适配。后台初始化失败写回登记并落盘到 driver.log，status 返回 diagnosticLog 路径。
