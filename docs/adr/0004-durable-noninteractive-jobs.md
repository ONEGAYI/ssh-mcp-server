# 首版非交互任务在断线后继续，重连后恢复跟进

## 背景与决定

用户的典型操作是 `make build` 和使用 `rg` 搜索大仓库，明确首版不需要交互式输入。用户选择 SSH 断线或本机客户端退出后远端任务继续，重连后恢复跟进；服务器自身重启后的自动重跑不纳入本轮推荐范围。交互式功能只评估复杂度与延期代价。

## 影响与边界

任务身份与记录不能仅存在于本机 MCP 内存或当前 SSH channel 中。恢复时应重新识别原任务、取得日志与最终状态，而不是重新运行原命令。本机停止等待不等于用户取消远端任务，等待期限与任务执行期限必须在设计中区分。

任务恢复与唤醒原始 ZCode 对话是两项验收：找回日志不能替代完成结果的恢复跟进。ZCode 退出后如何重新登记后台等待、补发未处理结果仍需实测。远端执行器、记录格式、取消实现和具体恢复接入未定案。
