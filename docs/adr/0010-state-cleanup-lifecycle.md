# 状态与临时文件采用有保留期的协作式清理

## 状态

2026-09-13 用户确认下述生命周期、清理触发方式与空间额度。决策已接受，尚未实施；具体实现留待规格确定。

## 背景

用户不接受状态和临时文件无节制、无限期堆积。当前手动 cleanup 只清理已确认且达到期限的终态日志，读取凭据、旧 helper、小型任务记录及崩溃遗留临时文件没有统一回收机制。

## 已确认决定

- 采用懒清理与 MCP 服务在线期间的低频定时清理组合。服务启动、重连或执行操作时可触发懒清理；在线定时维护默认每小时一轮。两种触发需要节流及互斥，不能重复并发清理同一工作区。
- 本机状态由本机服务清理；远端状态通过已建立的远端连接清理。不额外安装远端常驻服务或独立定时任务。
- 用户接受：本机 MCP 退出或远端断连期间不保证远端到期数据被删除；下次连接时补做清理。保留期限表示可清理时间，不是精确删除时刻。
- 已完成且结果已确认的完整任务日志，从结果确认起默认保留 3 天；到期按上述机制清理。该期限不套用于运行中任务或未确认结果。
- 保留期限的二次配置不追溯已有记录：已有记录保持原定到期时间，新生成记录使用新期限，详见 [ADR 0011](0011-binding-reconfiguration.md)。
- 已完成且结果已确认的小型任务及传输记录（包括结果摘要和用于识别已执行操作的记录），从结果确认起默认保留 30 天，到期清理。过期旧请求必须拒绝，不得因为记录不存在而重新执行命令、重复提交传输或再次覆盖文件。
- 已结束但一直未被 Agent 确认的任务结果，从任务结束起默认保留 30 天；到期清理完整日志和结果详情，后续访问明确提示结果已过期、旧输出无法恢复。过期旧请求仍须拒绝，不能因结果清理而重新执行。本项不适用于仍在运行或结束状态无法确认的任务，也不把查询操作视为结果确认。
- 实施 30 天记录回收前，必须建立在逐条记录删除后仍能拒绝过期请求的机制；具体标识、协议迁移与过期判定方案留待实施规格确定。不能只给现有记录加删除期限而保留“无记录即允许新执行”的行为，也不能将期限偷换为无限保留全部去重记录。
- 任务或传输结果无法核实时，先查询原操作，不自动重跑命令或再次覆盖。从首次进入结果未知状态起默认保留 30 天，查询和核对失败不续期；到期停止自动恢复，并按清理机制删除结果详情、诊断及恢复记录，明确提示记录已过期、需要人工核对实际结果。不能以结果未知或尚未人工核对为理由无限保留这些记录；记录删除后仍拒绝过期旧请求。
- 上述记录到期不等于操作失败或已经停止，不自动终止仍在运行的任务，也不删除正式文件。辅助临时数据确认属于本服务且没有进程使用后清理；占用情况不明的数据继续核实，所需最小资源管理信息不包含已过期的结果、日志或诊断全文，并计入工作区额度。清理记录前须保证仍能识别和回收这些临时资源，具体机制留待规格确定。
- 已中断且确认没有进程正在使用的传输，其临时数据从最后一次实际传输进展起默认保留 3 天。单纯查询状态不延长期限；到期由清理机制回收临时数据，此后明确提示续传已过期、需要重新传输，不能伪装为可继续的原传输。尚无传输进展时的计时基准和占用确认机制留待规格确定；不能将该期限直接用于仍在使用的临时文件。
- 清理只处理本服务明确拥有且符合已确定回收条件的数据，清理动作须有界；不能通过不加区分的递归扫描删除用户文件或正在使用的数据。
- 读取凭据 readToken 连续 3 天没有成功的相关读取或编辑即过期并可回收。仅同一会话、同一文件的有效相关操作续期，失败请求、单纯查询和其他文件的操作不延长有效期；过期凭据即使尚未物理删除也不能用于编辑。
- 凭据过期后提示重新读取拟修改片段，不要求读取全文，也不复活过期凭据的旧已读范围。文件发生外部变化时仍立即使旧凭据失效，不等待 3 天；本服务成功编辑后按既有映射规则签发的新凭据不受此影响。
- 普通临时文件在操作成功或明确失败后立即删除不再需要的部分。崩溃遗留文件在下一轮维护中确认属于本服务、没有进程占用且不再用于恢复后清理，不额外设置数天的保留期；不能仅凭文件名或时间判断可删。
- 断点续传的临时数据仍按已确认的 3 天规则处理；提交结果尚不明确的文件先核对状态，不能作为普通临时垃圾直接清理。上述决定只涉及本服务管理的临时文件，不清理用户命令自行生成的文件。
- 主动取消传输不适用意外中断的 3 天保留期：确认传输已停止后，立即清理未提交且不再使用的临时数据；已提交的正式文件不回滚。取消与提交并发时先核对实际状态，不能把未知提交结果当作可删临时数据。
- 远端 helpers/ 下的辅助程序仅保留当前版本，以及仍被活动任务或连接依赖的版本；确认无上述依赖的其他版本在下一轮维护时清理，不永久保留历史副本。需要回退时，从对应的本机离线包重新部署，不将远端历史目录当作回退备份。
- 旧辅助程序版本的回收必须核对跨进程使用情况，不能仅按目录时间或“不是当前进程版本”删除；当前版本及使用关系的登记、恢复和并发协调留待实施规格确定。
- 使用固定数量、可复用的锁文件，按目标标识确定锁的分配，不再为每个历史文件路径或任务编号无限新增锁文件。用户接受不同目标偶尔共享同一个锁而额外排队的性能取舍；锁数量及分组方式在实施规格中确定。
- 多目标操作必须对实际锁槽去重并按统一顺序加锁，避免重复获取同一锁或锁顺序不同导致死锁。固定锁文件在使用期间不删除重建；旧锁到新锁方案的迁移必须保证所有协作者一致，不能让两套互不协调的锁并行保护同一对象。具体迁移与跨进程协议留待规格确定。
- 达到空间额度时，先清理已过期且可安全回收的数据；仍不足则拒绝新增占用并说明原因。不为腾出空间而提前删除未到期续传数据、未确认结果或正在使用的文件。
- 默认每个工作区在本机和远端各有独立的 10 GiB 空间上限，可通过配置调整。计入本服务管理的状态、日志、辅助程序和临时数据，包括位于目标同目录的续传或编辑临时文件；不计入正式工程文件以及提交成功后的目标文件。多个工作区分别计量，不能把单工作区限额表述为整台机器总限额。
- 任务和传输启动前检查并预留所需额度，防止并发操作各自判断够用后合计超额。额度计算、运行期间追加申请及恢复机制留待规格确定；额度预留不等于操作系统保证磁盘空间，仍需处理其他程序占用磁盘或实际写入失败，不能宣称启动检查可以消除所有中途空间不足。

## 影响与待定项

- 工作区空间概览通过现有 remote_workspace 入口的可选参数按需查询，默认不附加用量信息，不新增独立 MCP 工具。参数名称可采用 includeStorage，最终 schema 在规格中确定。
- 开启查询时仅返回两端当前占用、预留额度、分类汇总及最近清理摘要，不逐条列出状态文件；返回须有界。程序统计与自动清理不调用模型，不能将维护过程变成持续向对话注入统计的循环。具体输出的 token 数需在最终格式确定后测量，访谈中的估算不作为保证。

- 在线使用期间自动处理到期数据，不需要用户定期手工执行 cleanup；停用后没有额外后台维护负担，但磁盘上可能暂留已过期数据。
- 中断传输临时数据的 3 天期限不代表其小型状态记录也按同一期限删除；已完成且结果已确认的记录适用确认后 30 天规则，结果未知的记录适用首次进入未知状态后 30 天规则。
- 空间计量的实现口径、额度预留的跨进程协调及崩溃遗留文件识别留待后续规格；不能仅凭文件名或更新时间认定文件可安全删除。
