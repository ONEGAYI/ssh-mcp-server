# 精确编辑支持已读范围全部替换与不重叠并行请求

## 状态

2026-10-10 用户确认最终共识并授权编写规格与测试先行实施，随后授权合并、清理与发布。实现已随 PR #42 合入，纳入 v2.5.0。本机回归与两轴独立审查通过；真实客户端和 CentOS 7 仍待人工验收。具体机制和资源预算见 [扩展规格](../design/scoped-edit-spec.md)。

## 背景

当前 `remote_edit` 只接受全文件唯一的 `oldText`，没有 `replace_all` 参数。调用凭据绑定整个文件版本；同一轮对同一文件发出多个独立编辑请求时，先成功的修改使其他请求的旧凭据失效，即使它们修改不同片段。

用户要求支持显式全部替换，并允许不冲突的同文件并行请求。用户选择保留未读内容的保护，接受全部替换仅覆盖已读命中；并行范围先限定为同一会话。

## 已确认决定

- `replace_all` 仅替换调用凭据已读范围内的全部命中，不修改未读命中。结果必须明确报告实际替换范围；存在未读命中时，不能宣称已经完成全文件替换。
- 本轮先支持同一 `sessionId` 下的多个独立并行编辑调用。`sessionId` 是恢复钩子提供的真实对话标识，`readToken` 是绑定会话、文件、版本和已读范围的读取凭据；凭据不同不代表会话不同。
- 冲突按读取版本中的实际修改区间判断。区间不重叠时允许；前面的增删应映射后面片段的位置。区间重叠时拒绝，即使两个请求修改相同目标并产生相同结果。
- 不同会话的修改仍使旧凭据失效；不把跨会话变更纳入本轮可合并范围。
- 用户接受推荐的 10 分钟短期变更追踪窗口，并限制记录数量和体积；记录超期或超额时旧凭据需要重读。调用方无需传入调用轮次参数；本决策不将现有 3 天闲置凭据期限变成连续追踪 3 天历史的承诺。
- `replace_all` 放在每条 `edits` 项内，默认 `false`，保持普通编辑的全文件唯一匹配；显式 `true` 才采用已读范围全部替换。同一次调用可以混合两种模式。

## 已确认保护规则

- 保留单次调用的原子性：任一编辑项校验失败或发生重叠冲突，整次调用不提交，不把冲突项静默跳过。
- 可追踪的中间变更限定为同一会话通过 `remote_edit` 成功提交的修改。Shell、整文件覆盖等其他写入仍使旧凭据失效。

## 影响与待定项

- 本决策补充 [ADR 0006](0006-large-file-version-checks.md) 中的唯一匹配和版本变化拒绝规则，实现以扩展规格为准，自 v2.5.0 纳入发行契约。
- 全部替换的范围与调用凭据有关；返回值和工具说明需要直接表达这一范围，避免把局部已读内容误称为整个文件。
- 支持并行调用需要证明中间变更没有影响请求的目标区间。不能仅删除版本检查，也不能仅凭当前文件还能找到 `oldText` 就接受旧凭据。
- 变更记录的具体数量和体积上限、持久化与清理机制、范围报告的有界表示及错误返回，在实施规格中确定。
