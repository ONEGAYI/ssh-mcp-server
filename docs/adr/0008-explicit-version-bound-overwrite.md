# 整体覆盖使用显式覆盖意图与目标版本检查

## 状态

2026-09-12 用户确认：不能要求模型读完旧文件全文，这对约 200 MB 网表不现实。决策已接受，尚未实施。

本决策调整 [ADR 0003](0003-file-tool-write-protection.md) 及首版 contracts.md 中整体覆盖须完整已读的要求，不改变局部 replace 的已读区间与唯一匹配要求。

## 背景

整体上传覆盖的意图是用指定的新文件替换旧文件，与基于已读片段修改局部内容不同。要求模型先接收旧文件全部内容会制造大量不必要的网络传输与上下文开销。

## 决定

- 整体覆盖已有文件（包括上传替换）不再要求模型读完旧文件，也不要求积累完整已读区间。
- 默认拒绝覆盖已有目标；调用方必须显式声明覆盖意图，并绑定服务已检查的目标版本。版本来自目标身份与元数据检查，遵循 [ADR 0006](0006-large-file-version-checks.md)，不能凭空填写版本来绕过检查。
- 提交前重新检查目标版本。目标变化时拒绝本次覆盖，要求重新获取目标状态并针对新版本明确发起操作，不能自动把旧覆盖意图用于新目标版本。
- 新内容先写入临时文件，完成所需校验后再提交；保留当前适用的路径、文件类型与元数据约束及协作锁边界。创建仍要求目标不存在，不隐式改成覆盖。
- 局部 replace 继续要求完整匹配片段已读、全文唯一原文匹配；整体覆盖的版本观察记录不冒充模型已读，不增加 readToken 的已读区间。
- 显式覆盖是工具调用的操作意图，不要求产品为每次覆盖新增人工确认弹窗；具体操作仍须在用户已授权任务范围内执行。

## 影响与保证边界

- 模型只需目标信息、覆盖意图及操作结果，无需通过工具输出接收旧文件全文。实际上传仍需把新文件内容传至远端。
- 放弃以模型完整已读为整体覆盖门槛，保留默认不覆盖和版本冲突检查，防止意外替换已变化的目标。
- 元数据检查不能证明所有内容变化均可发现，对不遵守协作锁的外部写入也不承诺消除最后一次检查与提交之间的竞争；沿用 ADR 0006 的边界。
- 目标版本观察入口、覆盖参数与记录形式留待实施规格确定；传输摘要、断点续传及提交结果恢复策略仍需后续决策。
