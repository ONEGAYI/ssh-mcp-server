# 大文件上传与下载支持断点续传

## 状态

2026-09-13 记录用户确认：本轮支持断点续传。决策已接受，尚未实施；当前上传、下载没有持久化传输恢复记录。

## 背景

约 200 MB 文件在网络中断后从头传输，会重复占用网络并增加等待时间。仅将数据分块并不足以支持断点续传，还需要在中断后识别原传输并验证已有数据。

## 决定

- 上传和下载均纳入本轮断点续传范围。
- 耗时上传下载支持后台执行和进度查询，完成后回传结果，使 Agent 可以继续其他工作。断线后跟进同一传输，不重新创建一份；后台入口、等待回传与恢复的具体接入沿现有客户端约定在规格中明确，不能只返回标识就宣称完成回传已实现。
- 采用分块校验支持续传，传输完成时再核对完整文件的 SHA-256。内容校验在两端执行，不为最终校验额外通过网络传输一遍全文；源版本稳定性和目标提交检查仍须独立保留。这不同于已取消的每次局部读写全文哈希要求。
- 记录原传输的归属、源与目标、源版本及已确认传输进度。重连时确认源文件未变化、已传分块有效，再继续原传输，不能只凭临时文件长度信任已有内容。
- 上传先写入临时文件；全部传输完成并校验后才提交正式目标。覆盖已有目标继续遵循 [ADR 0008](0008-explicit-version-bound-overwrite.md) 的显式覆盖意图与目标版本检查。
- 源文件变化或已传数据不能通过校验时，不得把不同版本的数据拼接为成功结果；具体重启或恢复响应留待实施规格确定。
- 传输的小型状态记录分别放在本机和远端各自的工作区状态目录下，使用 `transfers/` 子目录并按传输标识隔离；实际接收的临时文件放在接收目标同目录，供完整校验后的提交使用。该位置安排已由用户确认。
- 用户主动取消传输后，确认传输已停止，再立即删除尚未提交且不再使用的临时数据，不保留 3 天续传窗口；意外中断仍适用 3 天规则。已提交的正式文件不因取消回滚，取消与提交并发时须先核对实际状态再报告结果。
- 提交结果未知时查询原传输，不自动再次覆盖；从首次进入未知状态起默认保留结果、诊断及恢复记录 30 天，到期清掉记录并停止自动恢复，提示需人工核对。记录删除后仍拒绝过期旧请求；正式文件不删，临时资源回收遵循 ADR 0010 的占用检查，不能以结果未知为由无限保留结果记录。

## 影响与待定项

- 新增传输状态与临时数据管理，避免断线后盲目从头传输。
- 已确认意外中断且无进程占用的传输临时数据从最后一次实际进展起保留 3 天，查询不续期，到期清理后提示续传过期。已完成且结果已确认的小型传输记录从确认起保留 30 天，过期旧请求拒绝，不能因记录清理而重复提交。空间额度与回收边界见 [ADR 0010](0010-state-cleanup-lifecycle.md)。其他记录期限、分块校验细节与提交结果恢复尚待明确；本决策不将现有普通下载临时文件视为已支持持久续传。
- 本轮先实施 CentOS 7，Windows 远端完整适配由 [Issue #4](https://github.com/ONEGAYI/ssh-mcp-server/issues/4) 另行跟踪，当前 helper 仍依赖 Linux/Python。
